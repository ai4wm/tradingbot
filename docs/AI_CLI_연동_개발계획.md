# 앱 내 AI 분석과 감시 개발 계획

작성일: 2026-11-20

종목을 고르고 기다리는 일, 뉴스와 주문 기록을 확인하는 일, 장 마감 후 복기를 앱 안에서 이어갑니다. Codex와 Claude CLI를 연결하고, 앱이 가진 자료를 질문에 맞게 전달합니다. 목표는 화면을 지켜보는 시간을 줄이고 종목 선택과 시스템 동작을 근거로 이해하는 것입니다.

첫 완성품은 분석창의 AI 탭입니다. 선택 종목 분석, 관심종목 비교의 기초, 확보된 주문 로그 설명, 대화 저장부터 완성합니다. 이후 시장 흐름과 조건 감시, 상세 주문 기록과 복기를 연결하고, 우분투에서도 같은 분석 기능을 쓰도록 확장합니다. 실제 주문 실행과 기존 점상한가 기능의 서버 이전은 기존 자동 단타 개발 계획에 따라 별도로 진행합니다.

## 하루 동안의 사용 흐름

| 시점 | 질문 또는 동작 | 앱이 제공할 결과 |
| --- | --- | --- |
| 장 시작 전 | 오늘 볼 종목을 정리해 주세요 | 전일 강한 종목, 새 뉴스, 일봉 위치, 감시 후보와 제외 이유 |
| 장중 | 이 종목은 왜 움직이나요 | 새 재료와 기존 재료 구분, 가격과 거래량 변화, 근거 링크 |
| 장중 | 이 중에서 누가 가장 강한가요 | 선택한 종목 간 비교, 테마 내 위치, 순위가 달라진 이유 |
| 대기 중 | 정해 둔 움직임이 나오면 알려 주세요 | 코드가 감시한 조건과 실제 충족 시각, AI의 상황 설명 |
| 주문 발생 후 | 왜 자동매도가 나갔나요 | 당시 설정, 기록된 잔량, 주문 전송과 접수 및 체결 순서 |
| 장 마감 후 | 오늘 무엇을 놓쳤나요 | 당시 후보와 이후 결과, 늦게 선택한 사례, 제외가 맞았던 사례 |

장전 보고와 장중 감시는 먼저 사용자가 시작하는 방식으로 제공합니다. 정기 실행은 사용자가 켠 작업만 실행하고, 화면 연결과 별개로 실행 상태를 표시합니다.

## 기능 우선순위

### 첫 단계는 종목 분석과 비교

종목명을 반복 입력하지 않도록 종토방, 상한가, 테마, 뉴스에서 선택한 종목을 AI 탭으로 보냅니다. 여러 종목을 선택하면 같은 기준 시각으로 비교합니다. 자동 첨부되는 자료 목록을 전송 전에 확인하고 바꿀 수 있게 합니다.

분석 버튼은 다음 다섯 개를 목표로 추가합니다. 첫 배포에는 종목 분석과 비교, 확보된 주문 로그 설명을 연결하고 시장 흐름 및 복기는 해당 단계의 자료를 갖춘 뒤 활성화합니다.

- 종목 분석: 상승 및 하락 재료, 일봉 위치, 거래량, 이후 확인할 움직임을 설명합니다.
- 대장 비교: 관심종목 중 누가 더 강한지 비교하고 차이를 수치와 함께 보여줍니다.
- 시장 흐름: 상승 및 하락 종목 수, 거래대금, 테마 확산과 약화를 설명합니다.
- 주문 점검: 주문 한 건이나 종목을 골라 자동매매 동작을 시간 순서대로 풉니다.
- 오늘 복기: 저장한 후보와 판단을 이후 결과와 비교합니다.

뉴스는 발표 시각과 실제 사건 발생일을 함께 확인합니다. 계약 상담과 계약 체결, 임상 진행과 결과 발표를 구분합니다. 새로운 재료인지 판단할 때 이전 기사와 공시도 함께 비교합니다.

대장 비교의 기본 계산은 코드가 맡습니다. 시장 및 테마 대비 상승 정도, 거래대금과 최근 증가 속도, 당일 고점에서 밀린 정도, 동반 상승 종목 수, 일봉 위치를 계산하고 AI가 설명합니다. 최초 가중치는 가설로 기록하고 결과로 검증합니다. AI가 매번 임의로 점수 기준을 바꾸지 않게 합니다.

### 두 번째 단계는 기다림을 대신하는 감시

가격 돌파, 돌파 후 유지, 거래량 증가, 비교 종목 간 강도 역전처럼 계산할 수 있는 조건을 코드로 감시합니다. AI는 조건이 발생했을 때 자료를 읽어 설명합니다. 매 틱을 모델에 보내지 않습니다.

사용자가 말로 조건을 요청하면 종목, 가격 기준, 거래량 기준, 감시 시간, 해제 조건을 설정표로 변환해 보여줍니다. 해석되지 않은 표현은 임의의 숫자로 바꾸지 않습니다. 사용자가 감시 시작을 누르면 해당 설정으로 실행합니다.

같은 사건은 한 번만 알리고, 조건 해제 후 다시 충족된 경우의 재알림 규칙을 둡니다. 시세가 끊기거나 오래되면 감시가 정상 작동 중인 것처럼 표시하지 않습니다. AI 설명이 늦더라도 조건 발생 시각과 기본 알림은 먼저 남깁니다.

### 세 번째 단계는 주문 이유와 실수 복기

자동매매 판단마다 해당 종목, 당시 설정 버전, 사용한 입력값, 판단 이유, 주문 요청과 응답을 연결할 수 있게 기록합니다. 접수, 미체결, 부분 체결, 취소 요청, 취소 확인을 별개 사건으로 다룹니다. 앱과 영웅문 등 외부에서 낸 주문도 확보된 식별 정보로 연결합니다.

설명 예시는 다음과 같습니다.

> 기록된 매수잔량이 설정한 기준 아래로 내려가 매도주문을 보냈습니다. 주문은 접수됐지만 체결되지 않았고, 이후 취소가 확인됐습니다.

입력값이 없는 과거 기록에는 기록 부족을 표시합니다. 잔량 감소를 곧바로 체결이나 특정 참여자의 의도로 해석하지 않습니다.

복기는 당시 판단을 먼저 고정해서 저장한 뒤 이후 가격과 비교합니다. 선택한 종목뿐 아니라 제외한 후보와 거래하지 않은 경우도 남깁니다. 거래 판단 성과는 실제 매매와 구분하고, 비용과 체결 가능성을 반영하지 않은 가상 결과를 실현 수익으로 표시하지 않습니다.

### 네 번째 단계는 두 AI 비교와 사용자 기준 축적

평소 질문은 선택한 AI 하나에 보냅니다. 중요한 질문에서 사용자가 교차 검토를 누르면 같은 자료를 다른 AI에도 전달합니다. 공통 판단, 다른 판단, 자료로 확인할 수 있는 차이를 나눠 보여줍니다. 의견이 같다는 이유만으로 정답으로 처리하지 않습니다.

사용자 기준은 별도로 저장합니다. 예를 들어 대장 우선, 일봉으로 후보 선정, 분봉으로 타이밍 확인 같은 원칙과 적용 범위를 기록합니다. 사용자가 수정하면 버전과 변경 이유를 남깁니다. 이는 다음 질문에 참고 자료를 붙이는 기능이며 모델 자체를 재학습시키는 기능은 아닙니다.

과거 사례 검색에서는 비슷하게 성공한 사례와 실패한 사례를 함께 보여줍니다. 판단 이후에 알게 된 정보를 과거 판단의 근거로 넣지 않습니다.

### 다섯 번째 단계는 개발과 운영 지원

분석과 별개로 개발 작업 공간을 둡니다. 오류 조사, 로그 비교, 기능 수정안, 검증 결과를 한 작업에 묶어 볼 수 있게 합니다. 코드 수정은 별도 작업 사본에서 수행하고 변경 내역과 검증 결과를 보여줍니다. 운영 중인 앱의 코드 교체, 재시작, 커밋과 푸시는 각각 명시적으로 요청한 작업에 한해 실행합니다.

영웅문 연동은 별도 기능으로 관리합니다. CLI 연결만으로 영웅문의 관심종목 편집 기능이 생기지는 않습니다. 공식 파일 가져오기와 관심그룹 조회를 활용하고, 화면 제어를 통한 자동 반영은 실제 지원 여부와 동작을 검증한 뒤 연결합니다.

## 화면 구성

기존 분석창에 AI 분석 탭을 추가합니다. 필요하면 이 탭을 별도 창으로 분리할 수 있게 확장합니다. 라이트 및 다크 모드를 따르고 마지막 제공자와 대화를 복원합니다.

| 위치 | 내용 |
| --- | --- |
| 상단 | Codex 또는 Claude 선택, 사용 가능 모델, 새 대화, 중지, 연결 상태 |
| 질문 위 | 선택 종목, 비교 대상, 첨부할 자료와 기준 시각 |
| 가운데 | 대화와 실행 중인 작업, 수치 비교표, 근거 링크 |
| 하단 | 질문 입력, 분석 버튼, 첨부 자료 확인 |
| 작업 목록 | 감시 중인 조건, 완료된 분석, 실패와 재시도 상태 |

모든 분석은 사실, 해석, 다음 확인 사항을 구분합니다. 시세와 뉴스의 기준 시각이 다르면 각각 표시합니다. 수집되지 않은 자료는 빠진 이유를 보여줍니다. 검증하지 않은 성공 확률이나 정확도 숫자는 붙이지 않습니다.

AI 답변에서 관심종목 추가, 종목 열기, 감시 설정 같은 작업을 선택할 수 있게 합니다. 앱이 제공한 동작만 실제 함수로 실행하고, AI가 출력한 문장을 실행 코드로 취급하지 않습니다.

## CLI 연결과 데이터 전달

Codex는 app-server의 표준 입출력 통신을 우선 사용합니다. Claude는 CLI의 구조화된 입출력과 스트리밍을 사용하고, 대화 유지와 기능 호출 요구가 커지면 공식 SDK 연결을 검토합니다. 두 제공자는 공통 화면을 쓰되 대화 식별자와 기록은 각각 관리합니다.

첫 연결에서 설치 위치, 버전, 로그인 상태와 사용할 수 있는 모델을 확인합니다. 로그인은 각 제품의 공식 절차로 처리합니다. 이 PC에서 설치를 확인한 사실과 우분투에서 실행할 수 있는 상태는 구분하며, 구독과 API 인증에 따른 사용 조건 및 과금은 실제 연결 방식별로 확인합니다.

앱은 별도 프로세스로 CLI를 실행하고 비동기로 결과를 읽습니다. 긴 분석 중에도 호가와 주문 처리가 멈추지 않도록 합니다. 표준 출력의 JSON 메시지를 분할 수신과 한글 인코딩까지 고려해 처리하고, 오류 출력은 답변과 분리합니다. 종료, 중지, 재접속 때 자식 프로세스와 대화 상태를 정리합니다. 일반 질문을 쉘 명령 문자열에 이어 붙여 실행하지 않습니다.

자료는 질문에 필요한 범위로 묶습니다. 묶음에는 종목코드, 기준 시각, 거래소, 출처, 사용 기간, 누락 구간, 계산 기준과 근거 식별자를 포함합니다. API 키, 토큰, 계좌번호 원문은 분석 자료에서 제외합니다. 뉴스와 종토방 본문은 분석할 자료로 다루고 앱 실행 권한을 정하는 지시로 사용하지 않습니다.

현재 종토방은 웹뷰 열람용입니다. 첫 버전에서는 사용자가 첨부한 글만 분석하고, 웹뷰를 띄웠다는 이유로 AI가 게시글 전체를 읽었다고 표시하지 않습니다. 자동 게시글 수집은 별도 범위로 정합니다.

처음부터 연결할 조회 기능은 선택 종목 정보, 관심목록, 일봉, 종목뉴스 및 공시, 상한가 이력, 테마와 시장 자료, 필요한 주문 기록입니다. 분봉과 호가 이력은 실제 확보한 구간만 추가합니다. 앱의 기존 시세 연결을 공유하고 분석 때문에 별도의 증권사 웹소켓을 반복 개설하지 않습니다.

주문 실행은 기존 매매 엔진이 담당합니다. AI가 설명한 매수 의견이나 뉴스 문장이 주문으로 실행되는 연결은 첫 버전에 포함하지 않습니다. 자동 주문 연결은 기존 자동 단타 개발 계획의 검증 단계와 운용 한도를 따릅니다.

## 사용량을 아끼면서 활용도를 높이는 방법

- 시세 통계, 거래량 비교, 중복 제거와 순위 계산은 코드가 수행합니다.
- 이전에 전달한 자료는 식별자를 유지하고 변경된 내용 위주로 보냅니다. 제공자가 지원하는 캐시는 실제 사용량으로 효과를 확인합니다.
- 반복 질문은 자료 기준 시각이 같을 때만 이전 결과를 재사용합니다. 새 시세가 들어오면 예전 분석임을 표시합니다.
- 기본은 한 AI로 실행하고 다른 AI의 검토는 사용자가 선택하거나 정해 둔 작업에만 적용합니다.
- 같은 종목의 연속 뉴스는 묶고, 예약 분석의 대기열과 중복 실행을 관리합니다. 주문에 필요한 조회를 우선합니다.
- 요청 횟수, 처리 시간, 제공자가 반환한 토큰 및 비용을 기록합니다. 제공되지 않은 비용과 남은 구독 한도는 추정값을 확정값처럼 표시하지 않습니다.
- 자동 분석의 최대 횟수와 동시 작업 수를 설정하고, 한도에 도달하면 새 AI 작업을 대기시킵니다. 기존 조건 감시는 계속 실행합니다.

## 개발 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | CLI 연결과 대화 탭 | 두 CLI에서 답변을 받고, 대화 이어가기와 중지가 되며 앱 화면이 멈추지 않음 |
| 2 | 종목 자료와 분석 버튼 | 선택 종목과 관심목록을 정확히 전달하고, 답변에서 사용한 자료와 시각을 확인할 수 있음 |
| 3 | 대장 비교와 시장 흐름 | 같은 시각의 후보를 같은 계산 기준으로 비교하고, 순위 변경 이유를 기록함 |
| 4 | 조건 감시와 분봉 보완 | 수신 중단과 재접속을 구분하며, 한 사건의 중복 알림을 막고 시점별 조건을 재현함 |
| 5 | 주문 설명과 장 마감 복기 | 실제 기록으로 주문 순서를 설명하고 당시 후보와 이후 결과를 분리해 비교함 |
| 6 | 두 AI 검토와 개인 기준 | 동일 자료의 의견 차이와 적용 기준 버전을 확인하고 과거 사례를 다시 찾을 수 있음 |
| 7 | 우분투와 웹 연결 | 서버에 설치 및 인증된 실행기가 작업을 수행하고 PC와 웹에서 같은 작업 상태를 확인함 |
| 8 | 개발 지원과 검증한 자동매매 연결 | 개발 변경 내역과 검증 결과를 검토할 수 있고 매매 연결은 별도의 운용 기준을 통과함 |

1단계와 2단계를 첫 배포 단위로 묶습니다. 종목 분석, 대장 비교의 기초, 주문 로그 설명을 사용자가 직접 눌러 쓰는 것부터 완성한 뒤 자동 실행 범위를 넓힙니다. 완료 날짜는 연결 시험과 데이터 범위 확인 후 산정합니다.

## 코드와 저장 계획

| 새 구성 | 역할 |
| --- | --- |
| ui/ai_assistant_tab.py | 대화 화면, 선택 종목, 분석 버튼, 작업 표시 |
| ai_cli_runner.py | CLI 실행, 제공자별 통신, 스트리밍과 중지 |
| ai_context.py | 종목과 시장 및 주문 근거를 질문에 맞게 구성 |
| ai_tools.py | 조회와 관심목록 관리 등 앱 동작 연결 |
| ai_sessions.py | 대화, 작업, 기준과 사용량 저장 |
| data/ai_assistant.db | 대화 및 분석 시점, 근거 묶음, 작업 결과를 운영 자료와 분리해 저장 |

기존 main.py에는 탭과 선택 종목을 연결하는 최소 변경만 넣습니다. 기존 매매 코드의 구조 개편을 함께 진행하지 않습니다. 대화와 분석 원본은 Git에서 제외하고 보관 기간 및 삭제 기능을 둡니다. 여러 기기에서 같은 자동 작업을 중복 실행하지 않도록 서버 이전 시 실행 주체를 하나로 정합니다.

검증은 임시 DB와 설정, 가짜 CLI 응답으로 먼저 수행합니다. 출력이 여러 조각으로 도착하는 경우, 한글, 오류, 시간 초과, 중지, 다른 종목으로 선택 변경, 오래된 시세, 대화 복원과 중복 실행을 확인합니다. 그 뒤 실제 CLI로 짧은 분석을 실행하고 앱 응답성과 자료 연결을 확인합니다. 운영 DB와 layout.ini를 시험용으로 바꾸지 않습니다.

## 효과를 확인할 기록

분석에 걸린 시간, 사용자가 화면을 확인한 횟수, 불필요한 반복 알림, 관심종목 교체 횟수, 후보별 이후 움직임과 누락된 자료를 남깁니다. AI의 설명이 맞았는지는 자료와 연결해 확인합니다. 대장 선택이 나아졌는지와 진입 및 청산 타이밍이 나아졌는지는 따로 평가합니다.

가장 먼저 구현할 묶음은 AI 탭, 두 CLI 연결, 선택 종목과 관심목록 첨부, 종목 분석과 비교 버튼, 대화 저장 및 중지입니다.
